# 示例任务书

> 这是一个**不涉及安全场景**的演示任务，用来验证框架能跑通。
> 演示重点：任务拆解 + 状态外置 + 证据分级 + 终止条件。

## 目标

调研 3 个开源项目（Node.js / Python / Go 生态各一个），产出一份对比报告。

每个项目需要收集：

- 仓库基本信息（star 数、最近提交时间、License）
- 依赖数量与更新活跃度
- 已知未修复的 issue 数量
- 是否适合作为新项目的技术选型

## 产出要求

写入 `work/findings.md`，结构：

```markdown
# 开源项目对比报告

## 摘要
<一句话结论 + 推荐项>

## 逐项对比

### <项目名>
- 证据等级：L3/L4
- 观测：<命令 + 实际输出摘要>
- 复现：<可回放命令>
- 评估：<适配场景与风险>

## 覆盖度
- 已覆盖：<做过的>
- 未覆盖：<没做的 + 原因>
```

## 验收标准

- 3 个项目都有完整条目，每条附**可回放命令**（如 `curl -s https://api.github.com/repos/<owner>/<repo>`）
- 数据标注**采集时间**（数据会变，"star 数"必须带时间戳）
- 无法确认的项标 L1/L2，**不要猜**
- 覆盖度章节写明哪些维度没查

## 约束

- 公开 API 限速内调用，**不要并发轰炸**
- 网络失败时记录错误并继续下一个项目，不要卡住
- 单个项目的原始输出不要直接贴进报告，摘要即可

## 终止条件

- 3 个项目全部完成 → 写入 findings.md，回复 `DONE`
- 无法访问外部网络 → 写入已尝试的过程与错误，回复 `STOP`
