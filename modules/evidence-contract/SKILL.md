# 证据契约

## 为什么需要它

长任务的最大风险不是"做不完"，而是**做完之后给出的结论不可信**。

跑 60 轮的任务，中间会产生几十条"发现"。如果这些发现没有统一的可信度标注，
最后汇总时就会变成一锅粥：确定的和猜测的混在一起，
下游（人或其他系统）无法区分，只能全部重验或全部采信。

**一条未证实的结论比没有结论更糟**——它会污染后续所有推理。

本契约定义统一的分级与交付标准，让"疑似"和"已确认"清晰分离。

## 四级证据分级

| 等级 | 名称 | 判定依据 | 可宣称 |
|------|------|---------|--------|
| **L1** | 理论推断 | 仅基于文档/配置/静态分析的推断，无任何验证 | 疑似（POTENTIAL） |
| **L2** | 间接证据 | 观察到异常现象/行为差异，但未确认成因 | 疑似（POTENTIAL） |
| **L3** | 部分实证 | 现象可稳定复现，且影响可合理推断 | 已确认（CONFIRMED，影响为推断） |
| **L4** | 完整实证 | 完整复现链 + 实际影响可观测 | 已确认（CONFIRMED，影响为实证） |

**核心规则**：

1. 证据不足的，**一律标 POTENTIAL**，禁止标 CONFIRMED
2. 只有 L3/L4 可进入 `confirmed` 清单；L1/L2 进 `suspicious` 清单
3. 无法判断等级时，**宁可降级**，不夸大
4. 证据等级是**当前状态**，不是最终判决——后续验证升级它

## 三分类框架

| 分类 | 定义 | 处理方式 |
|------|------|---------|
| **CONFIRMED** | 有 L3/L4 证据支撑 | 进主报告，附完整证据 |
| **POTENTIAL** | 有线索但证据不足 | 进"待验证"清单，标注**缺什么证据** |
| **RULED OUT** | 验证后排除 | 单独记录，写明排除原因，**不混入主报告** |

**"默认排除直到被证明"**：发现先按 POTENTIAL 记录，
只有证据链闭合才升级为 CONFIRMED。

`RULED OUT` 清单同样有价值——它防止后续重复验证同一件事。

## 可回放规范

每条 CONFIRMED 必须附一条**任何人可原样执行**的复现命令：

```bash
# 格式：完整命令 + 参数 + 目标对象
curl -i -s 'https://example.com/api/resource?id=123' -H 'Authorization: Bearer <TOKEN>'
```

要求：
- 命令**完整**（含路径/参数/必要头部），不省略关键项
- 敏感值脱敏为 `<TOKEN>` / `<REDACTED>`，但**保留结构**
- 附一句**期望结果**（"返回 200 且包含 X，正常应返回 403"）

**为什么重要**：长任务的执行过程无法完整回放（上下文已裁剪、环境可能已变），
唯一能传递下去的就是这条命令。

## 采集清单

每条 CONFIRMED 交付时逐项核对：

- [ ] 原始观测（命令/请求 + 返回摘要）
- [ ] 1 条可回放命令
- [ ] 差异对照（预期 vs 实际）
- [ ] 影响评估（基于事实，不夸大）
- [ ] 修复/改进建议（可操作）
- [ ] 证据等级（L3/L4）

**一次到位**：确认的当下就把这几项采齐。
不要"先记个大概，写报告时再补"——补的时候往往已经拿不到了
（环境变了、状态没了、要重新制造一遍）。

## 批量处理的边界

同类现象批量处理时（同一成因 + 结构一致）：

- 抽 2-3 个样本完整验证，成立后按"同类"批量记录
- 记录时注明**覆盖范围**与**已验证样本数**
- **只有差异化的才算新条目**：仅标识符不同（换 ID、换名字）不算

## 禁止事项

- ❌ 编造命令输出、文件内容、接口响应（无实际输出 = 幻觉）
- ❌ 把探索阶段的观察（"存在这个功能""配置看起来缺失"）称为已确认
- ❌ 用模糊词替代证据："似乎""可能""疑似"必须附具体观测
- ❌ 过度声明影响（有 A 现象就说能做到 B）
- ❌ 排除项混入主报告
- ❌ 把"计划要做"表述为"已完成"

## 落地产出

最终报告按此结构组织：

```markdown
## 摘要
<一句话结论 + 确认/疑似数量>

## 确认项（CONFIRMED）
### <条目名>
- 证据等级：L3/L4
- 观测：<原始证据>
- 复现：<可回放命令>
- 影响：<评估>
- 建议：<改进方案>

## 待验证项（POTENTIAL）
### <条目名>
- 现有线索：<已观测到什么>
- 缺口：<还缺什么证据才能确认>
- 建议下一步：<具体动作>

## 已排除项（RULED OUT）
### <条目名>
- 排除依据：<为什么不是问题>

## 覆盖度
- 已覆盖：<做过的部分>
- 未覆盖：<没做的部分 + 原因>
```

**覆盖度章节不可省**——它界定了结论的适用范围，
避免"没发现问题"被误读为"没有问题"。
