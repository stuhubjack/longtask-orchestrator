# longtask-orchestrator

**长任务编排框架** —— 让 LLM 可靠地跑完几十轮、上百步的复杂任务。

> 核心思路：把"单一超长上下文"换成"多角色分工 + 结构化交接"，
> 用空间换记忆。

---

## 它解决什么问题

LLM 处理长任务时会**记忆衰减**：对话越长，早期关键信息越容易被压缩或丢失，
导致任务中途丢失线索、重复劳动、前后矛盾。

根因不是模型不够聪明，而是**把状态全押在上下文里**——
上下文是易失的、有界的、会被压缩的。任务越长，赌注越大。

本框架的处理方式：

```
        传统做法                        本框架
   ┌──────────────┐            ┌──────────────┐
   │  单一长上下文  │            │   编排者      │
   │  状态全在里面  │            │  (只持有指针) │
   └──────────────┘            └───────┬──────┘
          ↓ 上下文膨胀                  │ 结构化交接
          ↓ 被迫压缩              ┌─────┴─────┐
          ↓ 信息丢失           ┌──┴──┐    ┌──┴──┐
       任务失败               │子任务│    │子任务│ ← 各自干净上下文
                             └─────┘    └─────┘
                                  ↓          ↓
                             ┌────────────────────┐
                             │  外部状态（磁盘）    │ ← 真正的记忆
                             └────────────────────┘
```

## 快速开始

```bash
# 1. 配置模型（任何 OpenAI 兼容接口）
export LONGTASK_API="https://api.openai.com/v1/chat/completions"
export LONGTASK_API_KEY="your-key"
export LONGTASK_MODEL="gpt-4o-mini"

# 2. 跑一个示例任务
python3 core/runner.py examples/demo-task.md work

# 3. 验证框架本身没问题（不需要 API key）
python3 scripts/smoke_test.py

# 4. 发布前检查敏感内容
python3 scripts/sanitize_check.py .
```

运行参数：

```
python3 core/runner.py <task_file> [workdir] [model] [max_turns] [seed_file]
```

## 三个核心机制

### 1. 上下文管理

**上下文不是记忆，是工作台。** 工作台要干净，记忆放在抽屉里（磁盘）。

- 预算分配：任务书 10% / 近期对话 40% / 工具输出 30% / 余量 20%
- 单条工具输出截断到 6k 字符（截断是必需，不是优化）
- 裁剪必须保持 `assistant(tool_calls)` ↔ `tool` 响应的配对

详见 [`modules/context-management/`](modules/context-management/SKILL.md)

### 2. 结构化交接

子任务之间只传**结论 + 路径**，不传全文：

```json
{
  "subtask_id": "s03",
  "status": "done",
  "summary": "一句话结论",
  "artifacts": ["artifacts/s03/result.json"],
  "next_hint": "给下一个子任务的线索",
  "evidence_level": "L3"
}
```

下游需要细节时**自己去读文件**。这是"用空间换记忆"的落点。

### 3. 终止校验（防假成功）

模型说 `DONE` 不算数——**产出文件真的存在**才算。

```
工具报错 → 模型看到返回内容 → 以为成功 → 宣布完成 → 实际什么都没产出
```

这是长任务里最难发现的失败（进程正常退出、日志无异常）。
框架在终止时校验产出，缺失则打回让模型自查。

## 设计权衡

| 决策 | 收益 | 代价 |
|------|------|------|
| 子任务独立上下文 | 信息保真、互不污染 | Token 消耗随子任务数增长 |
| 状态外置到磁盘 | 可续跑、可审计 | 需要设计文件结构 |
| 每轮单动作 | 可回放、失败可定位 | 轮次变多 |
| 工具输出截断 | 保住上下文预算 | 需落盘 + 按需读取 |
| 终止校验 | 拦截假成功 | 多一次模型往返 |

---

## 适用边界

**适合**：步骤数不确定、单步产出可能很长、需要多轮迭代探索的任务。

**不适合**：

- 步骤少于 5 步的简单任务（编排开销大于收益）
- 需要严格确定性的事务（LLM 决策引入不确定性）
- 实时性要求高的场景（每轮 LLM 调用有秒级延迟）

## 使用须知

本框架是**通用的任务编排基础设施**，不针对特定领域。
使用时应遵守：

- **只在你获得明确授权的范围内使用**。框架本身不判断授权，需要使用者保证
- 工具层执行任意 shell 命令，**请审慎配置运行环境与权限边界**
- 建议在隔离环境（容器/虚拟机）中运行，限制可访问的资源
